## 调用路径与验收

真实生产模型 YAML（不改 features）→ 当前 MoyuLargeLanguageModel._invoke →
真实 SDK 0.9.0 → 受控 requests/urllib3 传输 → 两站。
没有直接构造上游业务请求来代替插件测试，也没有替换 SDK 请求/消息/解析逻辑。

执行顺序严格为：国内非流式闭环、海外非流式闭环、国内流式闭环、海外流式闭环。
任何失败或未证实均暂停后续，包括普通回复 5 而没有结构化工具调用的情况。
因此两站非流式都通过才可能发送流式请求。

每个闭环两次请求：auto 选择本地 add(2,3)，核对上游与 SDK 解析出的 ID/名称/JSON
参数后实际执行加法；以同一个 tool_call_id 回传 5，确认后续回答完成。
第二轮不带新 tools。流式真正消费 SDK 生成器，并独立恢复上游工具分片作对照。
不执行模型提供的代码，不开放多工具；意外多工具返回暂停。

## 请求计数与重试审计

- SDK 0.9.0 的 OAICompatLargeLanguageModel._generate 在此路径直接调用 requests.post，
  没有应用层重试循环；本验证器直接走适配器 _invoke，不另套重试逻辑。
- requests 默认 HTTPAdapter 为 Retry(0, read=False)，但 Session 默认可跟随重定向。
  本入口明确把所有 retry 类别设为 0，并关闭 allow_redirects；3xx 暂停。
- 在 HTTPAdapter.send 实际发送边界前计数并落盘，超时/连接失败也计入；最多 10 次。
  正常计划仅 8 次，无自动排错补充请求、模型列表请求或凭据校验请求。
- 每次模型调用至多允许一次 dispatch；限制精确 URL、POST、模型 ID、max_tokens=256。
  校验工具定义、auto 和第二轮历史匹配后才发送；其他 HTTP 路径被阻断。
- 网络审计只允许受计数的传输区间联网，其他 SDK 辅助下载也不自动放行。
  SDK 导入前关闭 dotenv/环境设置源；拒绝 dotenv 文件打开和子进程。
- 报告固定为 scripts/fc_phase2_round1_report.json。若已存在，拒绝重跑，防止重新
  从零计数。不得为了重跑删除报告；后续恢复必须先人工核对累计尝试次数。

## 流式未证实的调查与证据局限

第 5 次（国内流式工具请求）的上游结构化工具 ID、名称、参数与 SDK 解析一致，
工具参数由 6 个分片恢复，实际执行本地 add(2,3)=5。
第 6 次发送前已经检查 assistant tool_calls、role=tool、tool_call_id 和结果匹配，
响应完成且没有继续工具调用，但合并后的 SDK 文本不严格等于字符串 5。

已发现验证器的检查存在误判风险：SDK 0.9.0 的
interfaces/model/large_language_model.py:724 会把 reasoning_content 包为 think 标签，
并与最终 content 一同输出；现有验证器直接合并全部 chunk 再比较 5。
新增离线复现测试证明：上游最终 content=5 且有 reasoning_content 时，同样会触发
final_answer_not_confirmed。这是验证器需要改进的已确认情形，但不是本轮实际第 6 次
响应的已确认根因。

原因是当前报告在成功断言后才记录第二轮证据；失败轮没有保存回答形态、思考字段标志、
usage 和响应哈希。进程已退出，不应伪造恢复原始响应或把未证实改写为通过。
已有 5 次请求的 usage 合计 1849 tokens（国内 1244、海外 605），不包含第 6 次，
不能当成全部用量或实际扣费。单价未核实，费用估算留空，未宣称账单被平台硬限制。
